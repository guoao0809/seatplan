# 多次排座 —— 设计文档

日期：2026-10-13
状态：待评审

## 背景

老师一学期要换 8 次（每周两次）座位，规则是固定的（如「蛇形大挪移」）：**除了备注里写明「不能同桌」的学生，其余每个人在整学期里都要轮换到各个位置**，并且保证公平。

现在 seatplan 一次只能排一张座位图，老师就得手动重复 8 次，而且每次都得自己记住上几次谁坐过哪里——这正是程序该干的活。

## 目标

- AI 排座弹窗新增「生成次数」，一次生成 N 次座位图（1~20，默认 8）。
- N 次是**链式**的：第 1 次基于当前主页座位图，第 2 次基于第 1 次的结果，以此类推。
- 「不能同桌」是**硬约束**，由程序逐轮校验，不能只靠模型自觉。
- 公平性是**可检验**的：程序出轮换统计表。
- N 张结果用**轮播**（左右箭头）浏览；应用到主页后，主页同样能轮播切换。

## 范围

**做：**

- AI 弹窗：生成次数输入框 + 逐轮生成 + 进度与实时思考过程 + 轮播预览。
- 硬约束：`不能同桌:张三,李四` 结构化备注 + 逐轮程序校验 + 冲突时重跑该轮（最多 2 次）。
- 公平性：`fairnessReport` 统计表（只报告，不改座位）。
- 主页：`seatRounds` + 轮播切换；主图拖拽只改当前这一轮。
- 追问两种范围：只重排当前这次 / 整体重排（N 轮全部重新生成）。
- 记录：`SeatRecord` 加可选 `label`（「第 3 次」）。

**不做（明确 YAGNI）：**

- 程序自动修正座位以达到公平（统计只报告）。
- 预置「蛇形大挪移」规则模板（规则仍由老师写在提示词里）。
- 断点续跑：中途取消就从头来。
- N > 20（超过 20 次一轮串行调用在时间上已不可用）。

## 数据模型

主页从「一张图」变成「一组图 + 当前下标」：

```ts
const seatRounds = ref<Grid[]>([...]); // Grid = (string|null)[][][]，与 ai.ts 一致
const roundIndex = ref(0);
```

- `seatGrid: Group[]`（现有的显示结构）仍是**唯一被渲染的东西**，切轮时由 `seatRounds[i]` 重建它。
- **N = 1 时箭头隐藏，行为与现在完全一致**——这是兼容老数据和老习惯的前提。
- 持久化：新增 `seatplan:rounds`（rounds + index）。读不到时用现有的 `seatplan:grid` 退化成单轮，老数据不受影响。
- 主图拖拽换座：改 `seatGrid` 之后**回写** `seatRounds[roundIndex]`，再照旧 `persistGrid()`。
- 导出图片 / AI 基准 / 记录，一律取**当前轮**。

## 生成流程

N 轮串行，每轮一次独立的 `ai_arrange` 调用。

### 每轮的 payload

复用 `buildMessages`，两处关键取舍：

1. **`history` 只带最近 3 轮**（不是全部 N 轮）：N=20 时把 20 张图塞进 payload 既无必要也浪费。
2. **新增 `roundStats`**：程序算的公平计分表（每人已坐前/中/后排、左/右各几次），让模型判断「谁还没轮过后排」时**不必翻历史图**。这是「保证公平」从口号变成可执行输入的关键。

### 每轮的 instruction

每次调用是**全新会话**，模型没有上一轮的对话记忆，所以规则必须每轮重述：

```
{用户写在提示词里的规则原文}

（这是本学期第 i 次换座，共 N 次。current 是上一次的座位图，
 按同样的规则继续轮换，不要一次跳到与上一次差异过大的布局。）
```

### 逐轮硬约束校验

```
生成第 i 轮 → deskmateConflicts(grid, noDeskmatePairs)
  ├ 无冲突 → 收下
  └ 有冲突 → 追加「上一版仍把『张三』和『李四』排成了同桌，必须拆开」重跑该轮
              最多 2 次；仍不达标 → 保留该轮 + 标黄警告（不静默放过）
```

冲突信息会一路带到最后：轮播切换器上的异常轮标记 + 统计表里列出。

### 取消

每轮开头检查 `aiReqId`（现有机制），`closeAi` 能掐断整条链。

## 公平统计（fairnessReport）

对每个人、每一轮：判断该座位属于前/中/后排（按排号三等分）、左/右（座号 0/1）、第几组，累计次数。

输出一张表：姓名 | 前排 | 中排 | 后排 | 左 | 右 | 各组次数。

**判定规则刻意朴素**：某人在 N 次里某一类位置**一次都没轮到**就标出来。不做统计检验——老师一眼就能判断，程序也不该假装懂「公平」的复杂定义。

放两处（共用一个小表格组件）：AI 预览右栏（可折叠）、主页座位图下方（可折叠）。

## UI

### AI 弹窗输入态

- 新增「生成次数」数字框：1~20，默认 8。
- 下方灰字给预估：`≈ N × 每轮耗时`（关推理 2~4 秒/轮，开推理 50~80 秒/轮）。**这行字必须有**——20 次开着推理是 20 分钟以上，用户有权在点之前知道。
- 按钮文案：「开始排座（N 次）」。

### 排座进行中

右侧显示「第 3 / 8 次 · 模型思考中…」+ 实时思考过程（复用现有 SSE 流式），已生成的轮次可先切换查看。

### 预览态

- 顶部/两侧：`RoundSwitcher` 左右箭头 + 「第 3 / 8 次」+ 异常轮标记。
- 右栏：将执行的操作（相对上一轮）、为什么这么排、可折叠的思考过程、可折叠的轮换统计。
- 底部：「应用到座位图」（应用**整组** N 轮）、「全部存入记录」、追问输入 + 范围选择。

### 追问范围

- **当前这次**：只重排 `roundIndex` 这一轮，`current` = 该轮。
- **整体**：带新要求把 N 轮从头重跑一遍（N 次调用，按钮上标注预计耗时）。

### 主页

座位图左右两侧出现 `RoundSwitcher`（仅 N > 1 时），显示「第 3 / 8 次」，可左右切。统计表在图表下方可折叠。

## 组件与文件

- **新增 `src/lib/rotation.ts`**（纯逻辑，自带 `runSelfCheck`，沿用项目里每个 lib 文件的写法）：
  - `parseNoDeskmate(note)` —— 解析 `不能同桌:张三,李四`；单向声明即对称生效（张三写了他不能跟李四同桌就够了）。
  - `deskmateConflicts(grid, pairs)` —— 逐轮查冲突，复用 `ai.ts` 里已有的 `deskPairsOf`（同桌 = 同一排相邻成对）。
  - `fairnessReport(grids, roster)` —— 统计表数据。
  - `roundStatsOf(grids, roster)` —— 喂给模型的紧凑计分表。
- **新增 `src/components/RoundSwitcher.vue`** —— 左右箭头 + 「第 i / N 次」+ 异常标记，AI 预览与主页共用。
- **新增 `src/components/FairnessTable.vue`** —— 统计表，两处共用。
- **改 `src/lib/ai.ts`** —— payload 加 `roundStats`；`buildMessages` 支持传入按轮自定义的 instruction（现在也能传，只是调用点变了）。
- **改 `src/views/SeatView.vue`** —— 次数输入、生成循环、轮播状态、追问范围、统计表挂载。
- **改 `src/lib/records.ts` + `RecordsView.vue`** —— `SeatRecord.label?: string` 并在列表里显示。
- **Rust 侧不改**。

## 错误处理

- 某一轮校验不通过（下标越界等）：该轮视为失败，中止整条链并报错（已生成的轮次保留在预览里，可继续看/应用）。
- 硬约束重试 2 次仍不达标：保留 + 标黄，继续下一轮（不因为一对学生毁掉整学期）。
- 网络错误 / 网关报错：中止并显示原始错误（沿用现有 `aiError` 通道）。
- 取消：`aiReqId` 作废在途请求，整条链停住。

## 验证方式

1. `cd src-tauri && cargo test`、`node src/lib/rotation.ts`（自检）。
2. `npm run tauri dev`：
   - N=1 时行为与改动前完全一致（箭头不出现、拖拽、导出、记录都不变）；
   - N=3、开着思考跑一轮，确认进度、实时思考、轮播切换、异常轮标黄都能看到；
   - 故意在两人备注里都写 `不能同桌:对方`，确认生成结果里这一对**每一轮**都没同桌；
   - 应用后主页能左右切 3 张，切到哪张拖拽换座只影响那一张；
   - 统计表里「一次都没轮到」的格子被标出来；
   - 追问「当前这次」只动一张，「整体」重跑全部。
3. 断电测试：生成到一半点 X / 取消，确认没有迟到结果回写、UI 不卡。

## 已知风险

- **耗时**：N 次串行，开着推理时每轮 50~80 秒，20 次可能 20 分钟以上。缓解手段只有提前告知 + 可取消；这是「交给 AI 逐轮算」这个选择的固有代价。
- **模型不遵守规则**：链式生成依赖每一轮都理解规则。缓解：规则每轮重述 + 公平计分表入 payload + 硬约束程序校验 + 统计表可验证。
- **公平的定义**：程序只统计「有没有轮空」，不判断「是不是够公平」。老师看到表能自己判断，程序不越权。
